# Provider metadata and structural compatibility

Audit date: 2026-09-20. Scope: the entire AgentBridge Python package, public
CLI/SDK/RPC wiring, persistence, packaging and the private GrantBridge boundary.
Fullbrain application code and GrantBridge's unrelated OAuth/provider internals
are outside this audit. This is a compatibility review, not proof that every
future provider change is supported or that the deployment is production ready.
This is a historical direct-adapter audit. AgentBridge v2 executes only Codex
through CLIProxyAPI; the old Claude adapter does not define a second
execution or account flow. Current v2 status is in
[implementation-status.md](../interface/implementation-status.md).

The current account usage surface reads sanitized CLIProxyAPI Management API
observations. Its account quota windows contain `model_id`, `used_percent` and
`observed_at` only. Claude and Grok upstream quota is unknown in the current
observer. The direct Codex earned-reset mutation, its `quota_resets` module
and CLI `accounts quota-reset` command were removed; the retained RPC method
reports unsupported. Historical native window parsers do not define the v2
account response.

## Rules for subsequent changes

1. Read model IDs, parameter values, context sizes and available quota from
   the selected proxy account's observations. Do not infer a capability
   from a model name, suffix, marketing label or another account's catalog.
2. Cite the schema, SDK type or native compatibility format used by an adapter.
   Preserve the observed version in acceptance evidence. A version match alone
   does not prove schema compatibility.
3. Preserve unknown, absent, false and zero as different observations. A
   missing catalog is unavailable; a valid empty catalog is a successful empty
   observation. No hardcoded models substitute for failed discovery.
4. Map known published enums deliberately. Unknown terminal states cannot
   signal success; unknown events remain gaps/provider events. New fields can
   be ignored or retained as bounded metadata, but cannot authorize execution,
   a credential binding or an approval.
5. Use native structured error codes/statuses before compatibility text
   matching. Keep text fallbacks bounded and explicit. Unknown evidence is
   captured safely for reviewed diagnosis; a new classification never grants
   permission, changes an observed outcome or authorizes a retry.
6. Add tests for actual structures plus absent fields, wrong types, additive
   fields, unknown enums and inconsistent identity before changing an adapter.
   Verify the final wheel and installed entry points, not only source imports.
7. Local size/time/freshness limits and the AgentBridge public schema are owned
   policies. Constants implementing those policies are legitimate. They must
   not be presented as provider limits or discovered provider capabilities.

## Fixed failure modes

- Missing catalog metadata no longer invents models, false capabilities or a
  retirement date derived from an upgrade target.
- Missing/invalid catalog pages and account shapes cannot appear as live empty
  success or authenticated identity.
- Future/naive observation times stay stale. Historical native reset expiry
  and scoped quota metadata remain distinct from current proxy observations.
  Temporal aliases cannot override explicit durations or collapse independent
  native windows. Rollout discovery rejects a sessions root linked to another
  account.
- Unknown native turn/tool states and sparse task patches do not invent success
  or restart a task. Refusals remain visible, and structured HTTP errors take
  precedence over generic text.
- Native copies reject internal symlinks, mismatched session/version metadata
  and incompatible SQLite generations. UPSERT preserves new destination fields.
- Recovery reads every event page; late unresolved tools stay unknown. Old or
  subagent retractions cannot erase a new main-assistant response.
- Authentication checks provider/attempt identity and known states; opaque new
  nested fields cannot enter stored/public credential evidence.
- Provider model IDs are opaque bounded strings, not local resource IDs. Local
  booleans cannot masquerade as numeric budgets/timeouts.
- Instance usage marks its observation bound; instance turn count is complete.

## Remaining explicit limits

- No public introspection source exposes every requested field on every
  provider. Missing account quota and host permission replies remain unknown
  rather than simulated from session cost or token counts.
- Claude usage endpoints, native session paths/indexes, legacy quota temporal
  names and CLI version formats remain compatibility knowledge. Unknown changes
  require a new adapter/review; they cannot be understood safely from arbitrary
  names alone. Effort parameter aliases encode known semantics, while values
  come from model metadata.
- Native transfer is not a transaction spanning files and SQLite. Transfer
  replay metadata is incomplete, and validate-only is eligibility checking,
  not a provider acceptance run.
- Export materializes history; the catalog subprocess output bound is checked
  after collection. This audit does not certify constant memory for arbitrary
  provider output or arbitrarily long histories.
- Image validation checks encoding/header/size, not complete format decoding.
  Process identity outside Linux has the resolution available from `ps`.
- Error text compatibility and unknown-version rules are explicitly limited.
  Structural fixture validation does not prove the meaning of an AI proposal.
  Active reviewed classifications cannot bypass safety blocks or retry work.
